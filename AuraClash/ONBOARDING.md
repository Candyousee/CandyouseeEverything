# AURA CLASH: Onboarding Funnel v1 (3 October 2026)

**This file:** how a brand-new player gets from "joined" to "hooked", every step we measure on the way, what each step should look like, and what we change when players drop off.

- **Rules and numbers:** `GAME-BIBLE.md` (tutorial: section 11; the first 8 minutes: section 14).
- **Timings:** `econ/RESULTS.txt` section 11 (generated by `econ/model.py`, so they stay in sync with the economy).
- **Saving and tests:** `CORE-GAME.md` (P27-P28).
- **Roblox API:** `AnalyticsService:LogOnboardingFunnelStepEvent`, `LogFunnelStepEvent`, `LogCustomEvent` (Roblox creator-docs, *Funnel events*).

## 1. What "onboarded" means

A new player is onboarded when they have **beaten boss 1, started zone 2 and seen why to come back**. In the model that takes about **5½ min** (boss 1) to **20 min** (boss 2) for an average player.

The onboarding promise, in the order the player feels it:
1. **"I'm getting strong"** (0:20): the first meditation, +40 POWER, the aura flares.
2. **"That felt good"** (0:25): the first PERFECT shatters a crystal slime.
3. **"I got paid"** (~1:50): the first SELL, a shower of coins.
4. **"I got a pet!"** (~1:55): the Light Fox hatch, then a guaranteed Rare.
5. **"I beat a boss and transformed"** (~5:30): the Stone Golem falls, BLAZE.
6. **"There's a whole new world"** (~5:35): Pyrora Dojo opens, Hatch ×3 unlocks.
7. **"I'll come back"** (end of session): the offline gain is explained, and the next goal is on screen.

## 3. Logging rules (so the data is clean)

Roblox documents four behaviours that can quietly corrupt a funnel:
- events are sent **only from the server, and only in published games** (not Studio);
- a **repeated step counts only the first time**;
- **logging a later step auto-completes every earlier one**;
- **breakdowns use only the values sent with step 1.**

So:
1. **Server only.** Every step fires from server code at the moment the server itself confirms the event (the kill, the sell, the hatch reveal, the quest completion, the boss win). **No step is ever triggered by a client RemoteEvent**, so exploiters can't fake funnel data.
2. **New players only.** Step 1 fires only when a **new profile** is created. Returning players never re-enter the funnel.
3. **Strictly in order.** The profile stores `funnelNext` (the next step to log, starting at 1). When an event happens **early** (e.g. the player finishes quest 1 before their first SELL), the server **marks it as done but holds it**. Step N is logged only after step N−1 has been logged, and any held steps then flush in order. **The server never logs a step out of order**, so Roblox never auto-completes a step the player didn't do.
4. **Once each.** After logging step N, `funnelNext` = N+1 is saved with the profile (ordinary progress). A rejoin continues from there. (If a crash loses the last ~60 s, the step re-logs once; Roblox ignores the repeat.)
5. **Step 1 carries the breakdowns** (custom fields, see 4). Nothing later can change them.
6. **Studio:** the same code writes to the **session log** instead (CORE-GAME 3), so playtest #1 produces the same funnel from day one.
7. **Budget:** about 22 funnel events + ~10 custom events per new player is far inside Roblox's rate limits. Never log per kill or per frame.

## 4. Breakdowns (custom fields at step 1)

Breakdowns only use the values sent with step 1, so they're decided at join:

| Field | Values | Why |
|---|---|---|
| `CustomField01` | **tutorial variant** (`A`, `B` …) | A/B-test the tutorial (section 7) |
| `CustomField02` | **server state at join**: `fresh` (≤ 2 players) / `busy` | does seeing other players' auras and pets help? |
| `CustomField03` | **join source**: `home` / `friend` / `other` (from the join data, if available) | do friends' invites onboard better? |

Device, platform, age group and country breakdowns come built in.

## 5. Moments that aren't in order: custom events

These matter, but they can happen at any time, so they're **not funnel steps**. They're logged once each with `AnalyticsService:LogCustomEvent(player, name, value)` (value = minutes since join):

| Event | Model time (average) | Why we watch it |
|---|---|---|
| `FirstPerfect` | under 0.5 min (playtest target: under 30 s) | the core skill clicks |
| `FirstOverdrive` | median 1.1, 90th pct 3.3 (weak players: median ~12) | the "wow" moment. Weak players reach it late |
| `MutationKill` | ~1.0 (the guaranteed Gold Shardling) | greed and surprise |
| `FirstPetLevelUp` | ~2.7 | the reward rhythm (GAME-BIBLE 1.1) |
| `FirstStar` | ~5.1 | the fusion system is found |
| `FirstKnockout` | rare | dying early is a churn risk |
| `BossLoss` (each, with the attempt number) | | the clash difficulty |
| `MeditateButtonUsed` | | the friction fix works (GAME-BIBLE 1.1) |
| `SessionEnd` (on leave: minutes played, value = last funnel step) | | **where people quit**, even mid-step |

## 6. The return funnel (day 2)

One-time funnel **`FirstReturn`**, logged with `LogFunnelStepEvent(player, "FirstReturn", tostring(player.UserId), step, name)`:

| Step | Name | Fires when |
|---|---|---|
| 1 | First session ended | the first session ends (`PlayerRemoving`), after onboarding step 3 or later |
| 2 | Came back | the player joins again within 7 days |
| 3 | Saw the offline gain | the "WHILE YOU WERE AWAY" card is closed |
| 4 | Played 10 min after returning | 10 min into the return session |
| 5 | Beat the next boss | a boss win in the return session |

Day-1 / day-7 retention itself comes from the Roblox retention dashboard; this funnel shows **what returning players do first**.

## 7. Targets and what we change

**Initial targets.** There's no live data yet, so these are starting bars. Replace them with real baselines after the **first 1,000 new players** of the soft launch.

| Stretch | Investigate if conversion is below | First things to try |
|---|---|---|
| 1 → 2 (tutorial meditation) | 95% | a bigger MEDITATE hand; start sitting automatically on spawn; shorten to 15 s |
| 2 → 3 (first kill) | 95% | auto-target the nearest Shardling; a bigger hold-release prompt on mobile |
| 3 → 5 (sell, first egg) | 90% | the SELL prompt as soon as the storm is full; the hand walks them to the egg |
| 5 → 10 (zone 1 quests) | 85% | more quest-bar flashes; at step 8 (the slowest), a bonus at 3 hatches |
| 10 → 11 (attempting boss 1) | 90% | a glowing path to the arena; a "the Golem awaits" banner; the Trial button on the HUD |
| 11 → 12 (winning boss 1) | 85% | a softer Golem clash for the first attempt; clearer red-flash prompts |
| 12 → 13 (into zone 2) | 90% | an auto-teleport to Pyrora Dojo after BLAZE |
| 13 → 22 (zone 2) | 70% | at step 16 (the longest stretch), a bonus at 3 hatches; a zone 2 tutorial hand for the Hatch ×3 button |
| `FirstReturn` 1 → 2 | (Roblox day-1 retention) | a "your Power keeps growing while you're away" card at the end of the first session; the next boss shown on the login screen |

**How changes are tested:** a new tutorial version gets a new `CustomField01` value (e.g. `B`). New players are split 50/50 at join, and we compare the funnels for at least 1,000 new players per variant before keeping one. **Never change two things in the same variant.**
